# DB-IMP-003 — Market/FX artifact preflight validator

**Status:** Implemented as a read-only artifact validator; this does not activate or certify feeds for production.

## Implementation

- Reusable module: `src/preflight/market_fx.py`.
- CLI: `python -m src.scripts.market_fx_preflight`.
- Tests: `src/tests/test_market_fx_preflight.py`.
- Usage: `docs/market_fx_preflight.md`.
- Sample output: `database/reports/market_fx_preflight_sample.json`.

The validator computes SHA-256, byte size, type, and Excel worksheet names. MarketDaily validates row widths, the approved Jalali date and numeric fields independently of identity, preserves `Value` independently, and uses a consistent non-empty CSV `Ticker` as `codal_symbol` for economic keys. Missing or inconsistent ticker blocks only the economic-key checks. FX checks the approved Jalali date and sell-rate column only, preserves source cell coordinates and values, uses the approved `EXCHANGE_CENTER` USD/IRR identity, and performs no rate conversion. Duplicate FX keys are checked across worksheets. Both report source identity, publication identity, artifact identity, revision identity, and separate provenance timestamps. The tool makes no database connection and performs no ingestion.

## Current evidence and limitations

The checkout contains the two named artifacts. The FREE_MARKET file scan returned `BLOCKED_NO_SAMPLE`. CODAL and EXCHANGE_CENTER are owner-approved semantic identities, but publisher/profile linkage remains unverified. `source_published_at`, `source_available_at`, and revision identity are `UNKNOWN`; `ingested_at` is `NOT_INGESTED`. A matching artifact hash does not establish publisher identity or revision order. Validation does not imply production readiness.

The validator does not infer FREE_MARKET structure, use `Final/Open/High/Low`, calculate `Volume × Close`, select a winning duplicate, use last-arrival-wins, or convert FX values. Identical duplicate economic rows are warnings; conflicting duplicates fail closed.
