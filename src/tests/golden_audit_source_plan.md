# Golden Audit Source Investigation Plan

## 1. Current status

The repository currently contains a valid Stage 1 production pipeline and a locked architecture, but it does not contain a valid independent Golden expected dataset for the representative CODAL PDFs.

The production path is:

PDF sample
  ↓
acquire_codal_pdf / extract_raw_lines_from_pdf
  ↓
RawLineInput[]
  ↓
ingest_codal_report()
  ↓
Report / ReportVersion / RawFinancialFact

This path is valid for production validation and ingestion contracts, but it is not a valid Golden source because the expected values are generated by the same production path being audited.

The previous blocked specification remains correct:

GOLDEN ACCURACY AUDIT: BLOCKED — INDEPENDENT SOURCE OF TRUTH REQUIRED

## 5. Can an independently verified Golden Dataset currently be created?

No.

### Why not

The repository does not currently contain the required independent source material for the representative PDFs. Specifically, it lacks:

- exact official CODAL identifiers for the four PDFs;
- authoritative report URLs or canonical report records;
- report metadata from official CODAL publication;
- a verified values dataset independently maintained outside the extractor pipeline;
- a trusted manually curated dataset with provenance.

There is therefore no valid Golden dataset that can be created without inventing or reconstructing values from the production path.

---

## 6. Minimum external evidence required to unblock Golden Accuracy

A valid Golden source must provide the following evidence for every fact included in a limited Golden Dataset subset. A subset may support only a limited-scope audit; it must not be used to claim complete financial correctness for the full PDF or report:

- exact PDF identity or official report identifier;
- CODAL tracking ID;
- official report title and type;
- company identity;
- financial period;
- publication datetime;
- version/restatement metadata;
- source section and row/column where meaningful;
- raw item name and code;
- exact numeric value;
- explicit NULL vs Decimal("0");
- unit and currency;
- provenance to the official CODAL source.

Without these items, any expected-value dataset would be speculative or derived from the same pipeline under test.

---

## 7. Preferred future Golden source

The only realistic valid future source is an official or independently maintained CODAL-backed dataset that is not generated by the repository extractor.

### Preferred characteristics

- official CODAL publication metadata;
- exact report URL or canonical tracking ID;
- independently maintained spreadsheet or JSON manifest;
- reviewed and versioned expected values;
- exact Decimal numeric storage;
- explicit NULL handling;
- provenance metadata for each fact;
- no dependency on the production extractor or its DB rows.

### Would this satisfy independence?

Yes, if and only if the dataset is created by a party or process outside the production ingestion flow, and the source documents can be independently traced back to the official report.

## 9. Exact Decimal and NULL handling for a future valid Golden dataset

When an external source becomes available, the Golden record must retain exact decimal semantics:

- Decimal("0") means explicit zero
- None means NULL / missing
- Decimal("0") != None
- exact Decimal comparison only
- no float tolerance unless an explicit contract requires it

Provenance must trace each fact through:

RawFinancialFact
  ↓
ReportVersion
  ↓
Report
  ↓
official source metadata

This is required for auditability.
