The purpose is to answer one question only:

## 4. Candidate sources investigated

### A. Repository/test metadata

These are explicit internal clues but not authoritative evidence.

Examples:
- synthetic titles in tests such as "CODAL_SAMPLE" and filename-based labels
- generated sample IDs like "CODAL-PRODUCTION-SAMPLE-1"
- local:// URLs and example.invalid URLs in test fixtures
- persisted Report records in the database created by the production ingestion path

Rejected because:
- they are generated by the system under investigation
- they are not independent CODAL metadata
- they are not official report identifiers

### B. PDF embedded metadata

The PDF files include metadata such as:
- /Creator: Chromium
- /Producer: Skia/PDF m79
- /CreationDate
- /ModDate

Rejected because:
- these values are file-generation metadata only
- they do not identify the official CODAL report record
- they do not provide a canonical CODAL URL, report number, or version ID

### C. Visible document text inside PDFs

Examples from the local PDF text:
- company names such as Bank Mellat, National Industries of Steel, etc.
- report types such as monthly activity, interim financial statements, consolidated statements
- dates such as 1403/12/30, 1405/12/29, 1404/09/30
- restatement language and title fragments

Accepted only as clues, not as authoritative evidence.

### D. Official CODAL source

The official CODAL site was considered as the authoritative source for direct verification.

Current status:
- no exact CODAL record match was established for the four representative PDFs within the repository and this investigation environment
- no authoritative CODAL URL or report ID was confirmed for any of the four files

Therefore, the official-source path remains unresolved and the identity for each sample remains UNVERIFIED.

## 6. Explicit distinction between evidence types

### Repository/test metadata

This category includes:
- test names
- synthetic IDs
- filename-based metadata
- local:// sample URLs
- produced `Report` and `ReportVersion` rows

Status: unusable as authoritative evidence.

### PDF clues

This category includes:
- visible company name
- visible report title fragments
- visible report type
- visible period dates
- visible restatement wording
- PDF metadata timestamps

Status: useful for discovery only; not sufficient to establish official CODAL identity.

### Authoritative CODAL metadata

This category would include:
- official CODAL report URL
- official CODAL report ID / tracking ID
- official report title
- official company name as published by CODAL
- official report type
- official publication datetime
- official financial period and revision metadata

Status: required for verification; none established for these four files in this investigation.

## 9. What is still required before Golden Dataset construction

Before any Golden Dataset can be constructed, the following prerequisite is required:

1. Obtain the exact official CODAL report record for each representative PDF from an authoritative source.
2. Record the official CODAL URL and exact tracking/report ID.
3. Confirm company, title, report type, financial period, and publication datetime from the official source.
4. Confirm version, restatement, or correction metadata.
5. Only then build the Golden Dataset using official identity and audited provenance.
6. After that, a separate Golden Accuracy stage may be implemented; it must remain distinct from the production extraction path and must not derive expected values from the system under test.

This investigation is complete only for identity discovery. It does not unlock Golden Accuracy.
